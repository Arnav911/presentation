# Presenton: AI-Powered Presentation Generator
**Comprehensive Project & Technical Overview**

---

## 1. Executive Summary
**Presenton** is an advanced, AI-driven platform that automates the creation of professional, data-rich presentations. Moving far beyond static template fillers, Presenton acts as a virtual presentation consultant. It utilizes large language models (LLMs) to actively research topics, build narrative architectures, and intelligently map content to highly responsive, visually stunning layout systems. 

This document serves as a complete overview of the project's architecture, workflows, feature sets, and recent technical milestones.

---

## 2. Core Generation Modes

The system offers two primary pathways for presentation generation:

### A. Quick Generation (Standard Mode)
A fast-track process where the user provides a prompt (e.g., "The Rise of Electric Vehicles"), selects a single visual theme, and chooses a predefined narrative flow. The backend processes this in a single multi-step LLM call, quickly outputting a finished deck.

### B. Guide Mode (Consultation Workflow)
This is the flagship feature of Presenton. Designed for high-stakes, professional decks, it simulates a McKinsey-style consultation through a 5-phase interactive process:

1. **Phase 1: Strategy Layer**
   - The AI conducts initial parallel web research on the user's topic to generate a baseline context.
   - The system queries the user on target audience, purpose, duration, and strategic emphasis.
   - A strategic blueprint is compiled and confirmed.
2. **Phase 2: Substance Layer (Deep Research)**
   - The backend runs parallel, real-time web searches across multiple search engines.
   - It synthesizes raw data into factual, data-first bullet points and crafts a "Core Message" elevator pitch.
3. **Phase 3: Structure Layer (Narrative Architecture)**
   - The LLM drafts a comprehensive, slide-by-slide outline allocating logical sections (Context, Strategy, Financials, etc.).
   - At this stage, the exact slide count requested by the user is rigidly enforced.
4. **Phase 4: Surface Layer (Design Direction)**
   - The AI recommends information density, color palettes (with hex codes), and typography based on the strategy.
5. **Phase 5: Execution**
   - Real-time generation of the slides. Content is strictly mapped to structured JSON constraints to ensure it effortlessly slots into the frontend rendering engine.

## 3. Product Features & Dashboard Capabilities

- **Interactive Storyline Editor**: Users can expand, collapse, and inline-edit the LLM-generated narrative outline directly in the dashboard before finalizing the deck.
- **Real-Time SSE Streaming**: During generation, the UI displays dynamic progress, streaming live tool executions (e.g., "Searching...", "Reading URL...") via Server-Sent Events (SSE).
- **Recent Decks System**: A persistent local history of all generated presentations mapped to an SQLite database, showing slide counts and relative timestamps (e.g., "Generated 2h ago").
- **Slide Editor Workspace**: A specialized view allowing users to manipulate individual slides manually using Tiptap for rich text, managing images/icons, and dynamically adding or removing slides.

## 4. Technical Architecture Stack

Presenton is a Monorepo featuring a decoupled microservices-like architecture:

### Frontend (User Interface & Renderer)
*   **Framework**: Next.js 14+ (App Router), React, TypeScript.
*   **State Management**: Redux Toolkit for complex application state (Presentation slices, Undo/Redo history tracking).
*   **Styling**: Tailwind CSS combined with custom Vanilla CSS for sophisticated glassmorphism and dynamic themes.
*   **Icons**: Lucide React.
*   **Key Engineering Highlight**: The **Flexible Smart Layout Engine (`FlexSlide`)**. Instead of static DOM trees, slides are rendered by evaluating a deeply structured JSON payload. The `FlexSlide` dynamically chooses between 8 different responsive UI formats (Timeline, KPIs, Flow Diagrams, Two-Column Comparisons) based on the content context generated by the LLM.

### Backend (AI Pipeline & API)
*   **Framework**: FastAPI (Python) for extremely fast, concurrent API routing.
*   **Database**: SQLite managed via SQLAlchemy ORM (designed for easy future migration to PostgreSQL).
*   **AI Orchestration**: Langchain paired with deep integrations into native LLM tool-calling APIs (Anthropic Claude 3.5 / OpenAI GPT-4o).
*   **Data Validation**: Pydantic models validate incoming/outgoing schemas strongly.
*   **Key Engineering Highlight**: **Dynamic Schema Mapping**. The backend tells the LLM precisely how many slides to produce by dynamically compiling a Zod/Pydantic schema (e.g., `generate_presentation_outlines.py`) forcing the LLM to return strict, machine-readable syntax.

## 5. Recent Technical Milestones & Fixes

Our recent engineering cycles have dramatically stabilized the rendering system and Guide Mode logic:

1. **Duration strictness & Slide Count overriding**:
   - *Issue*: Selecting "Medium (15-20 min)" for 12 slides inexplicably generated 8 slides.
   - *Resolution*: Repaired critical substring match overlaps in `guide.py` (`"5-10"` instead of `"5"`) causing the algorithm to misclassify duration queries. The system now strictly honors the exact user-selected timeline.
2. **Global Theme Enforcement Engine**:
   - *Issue*: Decks generated slides that jumped drastically between dark mode and light mode inconsistently.
   - *Resolution*: Implemented a `forceTheme` interceptor pattern in `useTemplateLayouts.tsx`. Global deck settings now reliably override LLM hallucinations, applying unified visual styles across the entire deck.
3. **Smart Visual Type Mapping ("VS" Slide Bug)**:
   - *Issue*: The AI was mapping title and cover slides to `duotone-split` algorithms designed for "VS" comparison formats, creating confusing layout structures.
   - *Resolution*: Remapped `cover`, `title`, and `opener` tags exclusively to the `icon-bullets` schema on the FastAPI server, providing clean, professional hero layouts for title pages.
4. **Data Grid Sub-Dividing (KPI Grid Fix)**:
   - *Issue*: Passing 5-6 data points to the KPI layout caused the 2x2 grid constraint on the frontend to shatter and overflow standard 720p constraints.
   - *Resolution*: Implemented responsive column algebra; the layout automatically switches to a safe 3x2 grid and restructures font geometries dynamically if `elements > 4`.
5. **Render-Breaking Icon Artifacts (`{icon}`, `[icon]`)**:
   - *Issue*: LLM logic occasionally returned JSON punctuation in icon names, breaking rendering.
   - *Resolution*: Created regex sanitization within `FlexIcon.tsx` to scrub raw data and smartly ignore invalid metadata strings (e.g. `_icon` or `null`).

## 6. Project Roadmap

Moving forward, the architectural priorities consist of:
*   **Export Pipeline Integration**: Build direct PDF and `.pptx` (PowerPoint) compilation endpoints using `python-pptx` natively via the backend.
*   **Asset Management Pipeline**: Connect Pexels/Unsplash APIs to auto-populate high-resolution contextual background imagery based on prompt embeddings.
*   **Multi-tenant Infrastructure**: Upgrade SQLite paradigms to PostgreSQL arrays; implement full OAuth/SSO systems for distinct user-tenant presentation libraries. 
*   **Component Extensibility**: Permit users to author and store their own `JSON/React` template blocks natively inside the dashboard interface.
